# Aiko - Руководство пользователя

## Доска

Доска показывает карточки проекта в трёх проекциях:

- **Stories** - story-карточки по этапам своего workflow.
- **Tasks** - task-карточки по этапам своего workflow.
- **Combined** - story и task вместе.

Перетащите карточку между колонками, чтобы перевести её на другой этап. Переход сохраняется с
optimistic concurrency; если карточка изменилась в другом месте, UI предложит перезагрузить.

## Карточки

Каждая карточка - папка в `.aiko` с `card.json` и Markdown-артефактами. Карточка хранит:

- `kind` - `story` или `task`;
- `title`, `workflowId`, `stageId`;
- `revision` - optimistic-ревизия;
- `ownPriority` и вычисленный эффективный приоритет (task смешивает своё значение с
  максимальным значением родителя по весам проекта);
- `declaredScopeFiles` (намеченные файлы/glob) и `actualChangedFiles` (что реально изменено).
  Файлы вне объявленного scope помечаются как out-of-scope.

В инспекторе редактируются название, приоритет и declared scope; видны связи, executions,
попытки агентов, прогресс и артефакты.

## Workflow

Workflow - упорядоченный список этапов. У каждого этапа есть название, инструкция агенту,
допустимые виды карточек, агент по умолчанию, требуемые артефакты и политики действий.
Редактируются в UI (кнопка **Workflow**). Удаление этапа с карточками отклоняется.

## Настройки

Два уровня настроек:

- **Глобальные** (`app-settings.json` рядом с базой) - defaults и выбор уровня демона.
- **Проектные** (`.aiko/settings.json`) - действующие значения для одного проекта.

По каждой секции проектные настройки перекрывают глобальные, которые перекрывают безопасные
defaults. Сейчас настраиваются: execution (режим workspace, лимит одновременных запусков,
политики scope-overlap и коммитов) и веса приоритета.

## Executions

У карточки могут быть stage executions. Execution владеет workspace и хранит историю
`AgentAttempt` (по одной на запуск агента). Прогресс, изменения scope, артефакты, коммиты и
handoff записываются. Агент при rate-limit передаёт execution другому агенту без потери истории.

## Коммиты

Политика коммитов проекта определяет, кто коммитит:

- `deny` (по умолчанию) - коммитите вы; агент не коммитит.
- `ask` - агент сообщает о коммите и ждёт вашего подтверждения (execution переходит в
  `waiting-for-user`; подтвердите через `aiko_approve_commit` или в UI).
- `allow` - агент коммитит и сообщает SHA.

## Память

Долговременная память проекта лежит в `.aiko/memory` как Markdown с полнотекстовым поиском.
Используйте `aiko_search_memory` / `aiko_store_memory` (или `/aiko-memory`) для решений,
соглашений и уроков.

## Кросс-проектные карточки

Агент в одном проекте может поставить story/task в другой проект. Созданная карточка хранит
происхождение (`originProjectId`); проект-цель просто видит, откуда она пришла.
