# Aiko - Руководство пользователя

## Доска

Доска показывает карточки проекта в трёх проекциях:

- **Stories** - story-карточки по этапам своего workflow.
- **Tasks** - task-карточки по этапам своего workflow.
- **Combined** - story и task вместе.

Перетащите карточку между колонками, чтобы перевести её на другой этап. Переход сохраняется с
optimistic concurrency; если карточка изменилась в другом месте, UI предложит перезагрузить.

## Карточки

Каждая карточка - папка в `.aiko` с `card.json` и Markdown-артефактами. Карточка хранит:

- `kind` - `story` или `task`;
- `title`, `workflowId`, `stageId`;
- `revision` - optimistic-ревизия;
- `ownPriority` и вычисленный эффективный приоритет (task смешивает своё значение с
  максимальным значением родителя по весам проекта);
- `declaredScopeFiles` (намеченные файлы/glob) и `actualChangedFiles` (что реально изменено).
  Файлы вне объявленного scope помечаются как out-of-scope.
- `size` - размер из сетки проекта, например `M`. Агент выставляет его по описаниям из сетки, а
  коэффициент размера умножает score карточки.
- `criterionValues` - оценки карточки по критериям, если критерии у проекта заданы.

Собственный score карточки - взвешенное среднее её нормированных значений критериев, либо её own priority,
если критериев нет; и то и другое умножается на коэффициент размера. Для task это значение затем
смешивается с максимальным родительским по весам проекта (ТЗ §10).

Страница карточки разложена в две колонки: слева scope этапа с объявленными и фактическими файлами и
критериями приёмки, отчёт последнего запуска, блок под diff коммитов, артефакты и история запусков; справа
состояние выполнения с исполнителями, триаж и оценка с рангом карточки на доске, связанные карточки
(родительские, дочерние и просто связанные - каждая ведёт на свою страницу), прогресс по критериям приёмки
этапа, скиллы этапа и параметры карточки (название, приоритет, размер, declared scope).

## Workflow

Workflow - упорядоченный список этапов. У каждого этапа есть название, допустимые виды карточек,
инструкция агенту, скиллы, которые агент вызывает **до** и **после** этой инструкции, разрешённые
исполнители и агент по умолчанию, обязательные артефакты (у каждого - политика на случай отсутствия) и
команды проверки результата. Редактируются в **настройках проекта**: панель показывает этапы конвейера и
позволяет менять их порядок, а клик по этапу открывает его в выдвижной панели справа. Проекту принадлежит
своя копия конвейеров, поэтому правка здесь не доходит ни до другого проекта, ни до проектов, созданных из
шаблона позже. Удаление этапа с карточками отклоняется.

## Настройки

Уровней три, от самого широкого к самому узкому, и побеждает более узкий:

- **Шаблон** (`templates/default/template.json` рядом с базой демона) - то, из чего создаётся новый проект:
  значения по умолчанию для выполнения, модель оценки (веса, критерии, сетка размеров) и конвейеры с их
  этапами. Именно этот уровень редактирует экран **Глобальные настройки**, и его правка действует на
  проекты, созданные после, и никогда на уже существующие.
- **Установка** (`app-settings.json` рядом с базой) - fallback уровня демона для тех секций, которые шаблон
  не задаёт. Aiko записывает его при создании проекта; экран его не редактирует.
- **Проект** (`.aiko/settings.json`) - значения, с которыми реально работает проект; они копируются при
  создании. Этот уровень и только его редактирует экран **Настройки проекта**.

Сейчас настраиваются: выполнение (режим workspace, лимит одновременных запусков, политики пересечения scope
и коммитов) и модель приоритета - веса смешивания, критерии с их диапазонами и инструкциями агенту, и сетка
размеров.

## Шаблоны проектов

Проект создаётся из **шаблона**, и шаблон определяет, с чего проект начинается: этапы каждого конвейера
с инструкциями для агента и требуемыми артефактами, проекции доски, стартовую память и значения по
умолчанию. Выбрать его можно в форме *Добавить проект* на дашборде, командой
`aiko init <path> --template <id>` или через `aiko_init_project`, посмотрев список в `aiko_list_templates`
(тот же список доступен как `GET /api/v1/templates`).

Шаблон **копируется** в проект, и дальше проект владеет своей конфигурацией. Правка шаблона - в UI или
в `templates/<id>/template.json` рядом с базой демона - действует на проекты, созданные после, и никогда
на уже существующие. В `.aiko/project.json` записаны `templateId` и `templateVersion`, поэтому проект
всегда может сказать, из какого шаблона он создан.

## Executions

У карточки могут быть stage executions. Execution владеет workspace и хранит историю
`AgentAttempt` (по одной на запуск агента). Прогресс, изменения scope, артефакты, коммиты и
handoff записываются. Агент при rate-limit передаёт execution другому агенту без потери истории.

## Коммиты

Политика коммитов проекта определяет, кто коммитит:

- `deny` (по умолчанию) - коммитите вы; агент не коммитит.
- `ask` - агент сообщает о коммите и ждёт вашего подтверждения (execution переходит в
  `waiting-for-user`; подтвердите через `aiko_approve_commit` или в UI).
- `allow` - агент коммитит и сообщает SHA.

## Память

Долговременная память проекта лежит в `.aiko/memory` как Markdown с полнотекстовым поиском.
Используйте `aiko_search_memory` / `aiko_store_memory` (или `/aiko-memory`) для решений,
соглашений и уроков.

## Кросс-проектные карточки

Агент в одном проекте может поставить story/task в другой проект. Созданная карточка хранит
происхождение (`originProjectId`); проект-цель просто видит, откуда она пришла.
