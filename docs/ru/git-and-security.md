# Aiko - Git и безопасность

Aiko работает на вашей машине и рассчитан на то, чтобы там и оставаться. Этот документ собирает в одном
месте, что защищает демон, как обращаются с секретами и как Aiko обходится с Git. Это пользовательский
спутник [`SECURITY.md`](../../SECURITY.md) из корня репозитория, который остаётся нормативной политикой.

## Модель безопасности

- Демон слушает **только loopback**. Запрос, у которого заголовок `Host` не является loopback, отклоняется
  с `400`, поэтому прокси или туннель перед демоном падает громко, а не тихо.
- Источники браузера проверяются: проходит только собственная страница демона - его схема и порт, на
  `127.0.0.1` или `localhost`. Любой другой origin, включая страницу другой программы на другом локальном
  порту, получает `403`, как и запрос, который браузер помечает `Sec-Fetch-Site: same-site` или
  `cross-site`. Ни одна страница не может встроить доску во фрейм (`Content-Security-Policy:
  frame-ancestors 'none'`).
- Cookie сессии браузера открывает только REST API доски: MCP-эндпоинт принимает токен только в
  `Authorization: Bearer`, а запись, которую аутентифицирует cookie, должна нести заголовок
  `X-Aiko-Request` - его шлёт доска и не может добавить форма на чужой странице.
- Репозиторий - это данные, а не доверенный ввод: идентификаторы из `.aiko` (типы карточек, id воркфлоу и
  этапов) должны быть простыми именами файлов, а документ, нарушающий правило, отклоняется с именем его
  файла. Каждый путь, который Aiko строит из них - каталоги карточек, память, воркфлоу, файлы агентов внутри
  проекта, - обязан оставаться внутри проекта и не может проходить через junction или символическую ссылку
  ниже его корня.
- Клиенты аутентифицируются **токеном доступа**. Браузер сопрягается один раз одноразовым кодом.
- `AIKO_INSECURE=1` отключает аутентификацию. Он существует только для локальной отладки, и включать его
  надолго нельзя.
- Данные проекта лежат в `.aiko` внутри проекта; собственное состояние демона - в `%LOCALAPPDATA%\Aiko`.
  Ничего никуда не отправляется, а снятие проекта с регистрации никогда не удаляет файлы с диска.

Чего модель **не** покрывает: у демона нет учётных записей и нет способа различить двух локальных
пользователей ОС, поэтому он исходит из того, что машина однопользовательская. Не открывайте порт через
обратный прокси или туннель - проверка loopback существует именно для того, чтобы это падало громко.

## Токен доступа

Токен создаётся один раз и переиспользуется между запусками демона:

```text
%LOCALAPPDATA%\Aiko\access-token
```

Он нужен и REST-вызовам, и MCP-эндпоинту. `aiko token show` печатает его, а `AIKO_TOKEN` позволяет задать
токен самому (иначе он генерируется и сохраняется).

Ротируйте токен, если он утёк - например, если файл конфигурации агента с ним попал в коммит: замените
содержимое `access-token` новым значением и перезапустите демон. Всё, что закэшировало старый токен
(сопряжённые браузеры, MCP-конфигурации агентов), перестанет работать, пока не будет сопряжено или
переустановлено заново.

Если вы видите `401 Unauthorized`, у клиента не текущий токен: пересопрягите браузер через `aiko ui` или
перепишите MCP-конфигурацию агента через `aiko agent install`.

## Сопряжение браузера

Интерфейсу нужен токен, поэтому браузер сопрягается **одноразовым кодом**:

- `aiko ui` запускает демон, если ни один не отвечает, сопрягает браузер и открывает доску;
- другой браузер на этой же машине сопрягается так же: снова запустите `aiko ui` (каждый запуск выдаёт
  новый код) или откройте `Aiko pairing URL`, который демон печатает при старте. Aiko слушает только
  loopback-интерфейс, поэтому браузер на другой машине до него не дотянется.

Код одноразовый: его использование убирает его из набора действительных. `AIKO_PAIR_CODE` фиксирует код
сопряжения на известном значении и предназначен для тестов и скриптов.

## Секреты в конфигурации агентов

MCP-эндпоинт требует тот же токен, поэтому `aiko agent install` записывает его в MCP-конфигурацию агента:

- Claude Code, Cursor и ZCode получают заголовок `Authorization: Bearer ...`;
- Codex получает имя переменной окружения `AIKO_TOKEN`, которую он читает вместо заголовка.

**Эти файлы конфигурации - секреты.** Инициализация проекта добавляет их в `.gitignore`, чтобы они не
попали в коммит случайно. Никогда не коммитьте файл с токеном; если такой просочился, ротируйте токен, как
описано выше.

## Политики Git

### Политика Git при создании проекта

Проект записывает **политику Git**, которая решает, как система контроля версий обходится с `.aiko`:

- `local-only` (у встроенного шаблона) - весь каталог `.aiko` добавляется в `.gitignore`, поэтому знание проекта
  остаётся на этой машине;
- `track-project-knowledge` - конвейеры, настройки и память `.aiko` остаются под контролем версий, поэтому
  правила проекта едут вместе с кодом.

Политика - часть шаблона: `aiko init` берёт её из шаблона, если в запросе не названа другая.

### Политика коммитов

**Политика коммитов** проекта отвечает, кто коммитит во время запуска этапа:

- `deny` (по умолчанию) - коммитите вы; агент не коммитит;
- `ask` - агент сообщает о коммите и ждёт вашего одобрения (запуск переходит в `waiting-for-user`;
  одобряете вы на доске - агент не может одобрить свой коммит сам);
- `allow` - агент делает коммит и сообщает SHA.

Aiko сама никогда не создаёт коммит: она только записывает то, о чём сообщил агент. `git` она запускает
только на чтение - `status`, `log`, `diff` и `show` для ветки, изменений и диффа карточки.
Поэтому политика - это правило, которое читает агент, а не то, что демон может за него исполнить.

### Политика пуша

**Политика пуша** отвечает на тот же вопрос для пуша из общего checkout, с теми же тремя значениями. Это
правило, которое читает агент, а не то, что Aiko исполняет: у Aiko нет собственного пуша, поэтому ничто не
может остановить запуск до вашего одобрения. Политику сообщает контекст, который агент читает первым, и её
же повторяет процедура `/aiko-run`. Пуш и работа с ветками за этими пределами - post-MVP.

## Сообщить об уязвимости

Не сообщайте об уязвимостях через публичные issue на GitHub. Используйте приватный отчёт GitHub на вкладке
**Security** репозитория (**Report a vulnerability**), как описано в
[`SECURITY.md`](../../SECURITY.md).
