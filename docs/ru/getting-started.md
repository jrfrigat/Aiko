# Aiko - Быстрый старт

Путь от чистой установки до завершённой задачи за несколько минут.

## 1. Запустите демон и откройте UI

```powershell
aiko serve     # в одном терминале
aiko ui        # в другом (открывает браузер и сопрягает его с демоном)
```

Остановить демон потом можно командой `aiko serve stop` - из любого терминала, независимо от того, где он был запущен.

## 2. Зарегистрируйте проект

В UI нажмите **Добавить проект**, укажите путь к папке проекта и выберите git policy. Имя проекта и его
ID подставляются из папки - `C:\work\Aiko` превращается в **Aiko** с id **aiko**, поэтому адрес проекта
читается как `/p/aiko/board`. Оба поля можно изменить до нажатия «Создать»; ID, который уже занят другим
проектом, будет отклонён. Aiko создаст каталог `.aiko` и зарегистрирует проект.

Можно и из терминала:

```powershell
aiko init C:\path\to\your\project --name "Мой проект" --id moj-proekt
```

`--name` и `--id` необязательны: имя по умолчанию берётся из имени папки, а ID - из слага, выведенного из
этого имени (кириллица транслитерируется: *Мой проект* даёт `moj-proekt`). Выведенный ID при совпадении
делается уникальным автоматически, а введённый вручную - отклоняется.

## 3. Подключите агента

Установите глобальную интеграцию агентов один раз (она добавляет MCP-запись Aiko, скиллы и память
во все найденные агенты), затем подключите агента к этому проекту:

```powershell
aiko agent install --project <projectId>
```

Затем перезапустите агента, чтобы он загрузил MCP-сервер проекта.

## 4. Создайте карточку

В агенте (внутри проекта):

```text
/aiko-init <templateId>   # только если проект ещё не зарегистрирован; шаблон решает, с чего он стартует
/aiko-create task Добавь страницу настроек   # укажите тип, затем что нужно
/aiko-create bug Не работает выпадающий список
```

Типы берутся из самого проекта: каждый workflow в **Настройках проекта - Workflow** и есть тип карточек,
поэтому тип, добавленный там (*Epic*, *Bug*), можно создавать сразу - `/aiko-create` читает контекст
проекта, а не перечисляет типы жёстко, и для каждого типа генерируется `/aiko-create-<тип>`.

Или простым языком: *"Создай задачу - добавить страницу настроек"*. Те же карточки создаются в
UI кнопкой **Карточка** на доске.

## 5. Ведите по этапам

Агент сначала читает контекст проекта, затем запускает карточку:

```text
/aiko-run TASK-1              # сделать то, что требует текущий этап карточки
/aiko-run TASK-1 review       # сначала перевести карточку на "review", затем выполнить
```

Отдельных команд на каждый этап нет: `/aiko-run` берёт этап из карточки, а инструкцию из проекта, поэтому
работает и в конвейере, который вы отредактировали или придумали сами. Перетаскивайте карточки между
колонками на доске для того же эффекта. Когда нужны файлы вне scope карточки, агент вызывает
`aiko_request_scope_expansion` и ждёт вашего решения.

## 6. Завершите и сохраните знания

`/aiko-run` сам завершает начатый этап, фиксируя фактические изменённые файлы и артефакты, поэтому
остаётся только шаг со знаниями:

```text
/aiko-memory       # сохранить долговременные решения и уроки
```

Коммиты подчиняются политике проекта (`deny` по умолчанию - коммитите вы; `ask` - агент
спрашивает; `allow` - агент коммитит). UI показывает доску, страницу проекта (статистика, скорость,
распределение), карточку (scope, критерии приёмки, дифф из git, обсуждение, запуски) и наборы workflow -
всё с live-обновлением по SSE.
