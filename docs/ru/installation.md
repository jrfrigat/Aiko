# Aiko - Установка

Aiko - локальный оркестратор ИИ-разработки: один loopback-демон, Kanban PWA, долговременная
память проекта и стабильный MCP-контракт для Claude Code, Codex, Cursor, ZCode и Cline.

Этот гайд описывает установку и запуск Aiko на Windows.

## Требования

- Windows 10/11 x64 (релиз - самодостаточная сборка win-x64).
- Для установки релиза больше ничего не нужно: ни .NET SDK, ни .NET runtime.
- [.NET 10 SDK](https://dotnet.microsoft.com/download/dotnet/10.0) - только если вы собираете и
  запускаете из исходников. Сборка из исходников публикуется framework-dependent, поэтому на этапе
  запуска нужен .NET 10 runtime.

## Установка

Одна строка в PowerShell:

```powershell
irm https://raw.githubusercontent.com/jrfrigat/Aiko/main/scripts/install.ps1 | iex
```

Установщик:

1. находит свежий релиз на GitHub (или указанный вами тег),
2. скачивает из него `aiko-<версия>-win-x64.zip`,
3. распаковывает в `%LOCALAPPDATA%\Aiko\bin`,
4. добавляет этот каталог в пользовательский `PATH`.

Ничего не ставится на всю машину, права администратора не нужны. Откройте новый терминал, чтобы
команда `aiko` подхватилась.

Установленная раскладка:

```text
%LOCALAPPDATA%\Aiko\bin\aiko.exe                 CLI
%LOCALAPPDATA%\Aiko\bin\aiko-stdio.exe           stdio <-> Streamable HTTP MCP-прокси
%LOCALAPPDATA%\Aiko\bin\server\Aiko.Server.exe   демон, PWA в server\wwwroot
```

В конце установщик спрашивает, с какими агентами работать, и записывает им глобальную MCP-запись,
скиллы `/aiko-*` и общую память (по сути `aiko agent install --scope user`). Enter - пропустить;
в агентов, которых вы не назвали, ничего не пишется.

### Параметры установщика

| Параметр | Действие |
| :-- | :-- |
| `-Version <tag>` | Установить конкретный релиз, например `v0.1.0`. По умолчанию - последний релиз. |
| `-InstallDir <path>` | Распаковать в другой каталог. По умолчанию `%LOCALAPPDATA%\Aiko\bin`. |
| `-Agents <ids>` | Подключить агентов без диалога, например `claude-code,codex`. |
| `-NoAgentSetup` | Не спрашивать про агентов (то же самое позже: `aiko agent install --scope user`). |
| `-NoPathUpdate` | Не менять пользовательский `PATH`. |

Параметры требуют формы со scriptblock, потому что `irm ... | iex` их не принимает:

```powershell
& ([scriptblock]::Create((irm https://raw.githubusercontent.com/jrfrigat/Aiko/main/scripts/install.ps1))) `
    -Version v0.1.0 -InstallDir D:\Tools\Aiko
```

### Установка из исходников

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1
```

Скрипт публикует текущее рабочее дерево framework-dependent (`aiko` CLI, демон, stdio-прокси) в тот
же каталог `%LOCALAPPDATA%\Aiko\bin`; на этапе запуска потребуется .NET 10 runtime.

Установите глобальные скиллы агентов (опционально, но рекомендуется - чтобы `/aiko-init`
работал везде):

```powershell
aiko agent install --scope user
```

## Запуск

Запустите демон (он слушает только loopback):

```powershell
aiko serve        # в этом терминале: лог здесь же, Ctrl+C останавливает
aiko serve -d     # в фоне: переживёт закрытие этого терминала
```

`-d` (или `--detached`) запускает демон с собственной невидимой консолью и файлом лога, поэтому закрытие
терминала - или Ctrl+C, которым он заканчивается, - больше не забирает демон с собой. Команда сообщает pid,
порт и путь к логу и возвращается, как только демон ответит на `/health`; лог по умолчанию лежит рядом с базой
как `daemon.log` и переносится через `AIKO_LOG_FILE`. На установку работает один демон: второй запуск скажет,
на каком порту уже работает первый, вместо падения на занятом порту.

Остановить его можно из любого терминала:

```powershell
aiko serve stop
```

Команда просит демон остановиться - на порту, который он сохранил при запуске, или на указанном через
`--port <p>` (так достаётся демон, запущенный вручную). Без локального токена доступа остановка
отклоняется, как и любой другой вызов API, а команда ждёт, пока порт действительно перестанет отвечать,
и только потом сообщает об успехе.

Демон может также запускаться при входе в систему - это выбор, который предлагает установщик (`-Autostart`,
а сам вопрос по умолчанию «нет»). Это командный файл в вашей собственной папке «Автозагрузка», поэтому
`aiko autostart status` покажет, настроено ли это, `aiko autostart enable` и `aiko autostart disable`
меняют состояние, а удаление файла вручную равносильно отключению:

```powershell
aiko autostart enable    # демон запускается при входе
aiko autostart disable   # и перестаёт это делать
```

Запись создаётся только тогда, когда её попросили: она указывает на установленную команду `aiko`, а
`aiko uninstall` снимает её вместе с остальной установкой.

Откройте UI - браузер сопрягается с демоном по одноразовому коду и открывает доску:

```powershell
aiko ui
```

UI нужен демон, поэтому `aiko ui` сначала запускает его в фоне, если ни один не отвечает: «сначала запустите
сервис, потом возвращайтесь» - не ответ на просьбу открыть доску.

`aiko status` показывает каталог данных, путь к базе, порт и состояние демона; когда демон не работает, он
дополнительно печатает, как его запустить, и хвост последнего фонового лога - именно там демон говорит, почему
остановился. Он же называет агентов, найденных в `PATH` без глобальной конфигурации Aiko: агент, поставленный
после Aiko, - обычное дело, и в строке указано, какой командой он подключается.

## Конфигурация

| Переменная окружения | Назначение |
| :-- | :-- |
| `AIKO_PORT` | Явный порт для следующего запуска; проверяется и сохраняется |
| `AIKO_URL` | Явный loopback-адрес (переопределяет выбор порта) |
| `AIKO_DATABASE` | Путь к базе SQLite (по умолчанию `%LOCALAPPDATA%\Aiko\aiko.db`) |
| `AIKO_LOG_FILE` | Файл, в который демон пишет лог; `aiko serve -d` задаёт `<data>\daemon.log` |
| `AIKO_TOKEN` | Фиксированный токен доступа (иначе генерируется и хранится в `access-token`) |
| `AIKO_PAIR_CODE` | Фиксированный код сопряжения (для тестов/скриптов) |
| `AIKO_INSECURE` | `1` отключает аутентификацию (только для локальной отладки) |

Демон предпочитает порт `24560`; если он занят - спрашивает другой порт (или выбирает свободный
из `18000-18999` в неинтерактивном режиме) и запоминает выбор в `settings.json` рядом с базой.

## Регистрация проекта

Либо в UI (кнопка "Добавить проект" на дашборде), либо из терминала:

```powershell
aiko init C:\path\to\your\project --name "My Project" --id my-project --git-policy local-only
```

`--name` и `--id` необязательны. Имя по умолчанию берётся из имени папки, а ID - это короткий адрес из URL
UI (`/p/my-project/board`); он выводится из имени, а кириллица транслитерируется в латиницу. Введённый ID
используется как есть или отклоняется, если он уже занят другим проектом; выведенный - при совпадении
получает числовой суффикс.

В UI в форме есть кнопка **Обзор**: она открывает список каталогов от демона, так что путь выбирается,
а не вводится. Папки, которые уже содержат `.aiko`, помечаются, а поле остаётся редактируемым для тех,
кто предпочитает вставить путь. Выбор или ввод пути сразу заполняет имя и ID, и оба остаются редактируемыми.

Это создаёт каталог `.aiko` (workflow, проекции, память) и регистрирует проект. По умолчанию
git policy - `local-only` (весь `.aiko` добавляется в `.gitignore`); `track-project-knowledge`
хранит workflow и память в системе контроля версий.

## Отключение проекта

Регистрацию можно убрать, ничего на диске не трогая - опечатка в пути, переехавший проект или
временный проект для проверки:

```powershell
aiko project remove <projectId> --yes
```

Уходят только регистрация и её SQLite-проекции. Каталог `.aiko`, workflow и память остаются на месте,
и `aiko init` по тому же пути зарегистрирует проект снова. В UI это кнопка с корзиной в строке проекта
на дашборде; в REST - `DELETE /api/v1/projects/<projectId>` (204 при успехе, 404 если регистрации уже
не было).

Удаление вместе с каталогом `.aiko` намеренно **не** реализовано: отключение существует, чтобы
отменить ошибку, а команда, которая заодно стирает файлы, не может быть поведением по умолчанию.
Удалите каталог сами, если нужен именно этот результат.

## Подключение агента

```powershell
aiko agent install --project <projectId>
```

Записывает project-scoped MCP-конфигурацию и скиллы `/aiko-*` для найденных агентов.
`aiko agent list` показывает, какие агенты найдены. Перезапустите агента, чтобы он загрузил
новый MCP-сервер.

## Обновление и удаление

- Обновление: повторно запустите установщик (релизный или из исходников) - бинари заменяются, данные
  и настройки проектов сохраняются. Параметр `-Version` фиксирует конкретный релиз, если свежий не
  нужен.
- Удаление: `aiko uninstall`. Команда останавливает запущенный демон, снимает запись автозапуска, если
  она есть, убирает каталог установки из пользовательского `PATH` и удаляет опубликованные бинари -
  запущенный `aiko` входит в их число, поэтому команда называет файлы, которые пришлось оставить; их
  можно удалить после её завершения. Повторный запуск сообщает, что снимать больше нечего.
- Что сохраняется: каталог данных (`%LOCALAPPDATA%\Aiko` - база, настройки, токен доступа, копии) и
  `.aiko` каждого проекта. Про них спрашивают отдельно, и по умолчанию оба *остаются*:
  `aiko uninstall --remove-data` удаляет базу и регистрацию всех проектов на этой машине,
  `aiko uninstall --remove-project-data` удаляет собственные каталоги `.aiko` проектов, печатая их
  список заранее. `--yes` подтверждает само снятие установки, а не удаление данных.

## Проверка

- `aiko status` - состояние демона, порт, каталог данных и агенты, найденные в `PATH` без глобальной
  конфигурации Aiko, каждый с командой подключения.
- `aiko doctor` - отчёт об установке: база, токен, порт, проекты и конфигурации агентов, указывающие на
  старый эндпоинт. Ничего не меняет; `aiko repair --fix` применяет найденные исправления.
- `GET http://127.0.0.1:<port>/health` - `healthy`.
- `aiko ui` - открывает доску.

Если `irm` блокируется политикой выполнения, запустите установщик явно:

```powershell
powershell -ExecutionPolicy Bypass -Command "irm https://raw.githubusercontent.com/jrfrigat/Aiko/main/scripts/install.ps1 | iex"
```

## Обновление установленного демона

Установщик распаковывает в `%LOCALAPPDATA%\Aiko\bin` **релизную** сборку; сборка из рабочей копии в эту
папку сама по себе не попадает. Чтобы перевести установку на более новую сборку:

1. Остановите работающий демон (действие «остановить» на экране демона, либо `aiko status` и затем остановка
   процесса).
2. Либо запустите установщик снова — он поставит последний релиз, — либо опубликуйте рабочую копию сами и
   скопируйте её поверх папки:

   ```powershell
   dotnet publish src/Aiko.Server/Aiko.Server.csproj -c Release -p:PublishAot=false -o .\artifacts\publish
   Copy-Item .\artifacts\publish\* "$env:LOCALAPPDATA\Aiko\bin" -Recurse -Force
   ```

3. Запустите демон снова и один раз перезагрузите доску.

Клиент раздаёт сам демон, поэтому уже открытая страница принадлежит той сборке, которая её отдала. Service
worker спрашивает у демона app shell первым и держит в кэше только файлы с хэшем содержимого, поэтому после
обновления достаточно одной перезагрузки. Когда работающий клиент старше того, что раздаёт демон, в шапке
появляется кнопка **«новая версия»** вместо того, чтобы прятать рассинхрон за здоровым бейджем.
